# PowerShell Script Signing Service

`script-sign` is a small Spring Boot service that applies a Windows Authenticode
signature to an unsigned PowerShell `.ps1` script. It uses a PKCS#12 code-signing
identity, SHA-256, and (by default) an RFC 3161 timestamp.

The API accepts script source as JSON and returns the signed source. The private
key and certificate never cross the API boundary.

## API

`POST /api/v1/powershell/signatures`

```json
{
  "fileName": "hello.ps1",
  "scriptContent": "Write-Output \"Hello\""
}
```

Successful responses include the signed script and non-secret signing metadata:

```json
{
  "fileName": "hello.ps1",
  "signedScript": "Write-Output \"Hello\"\r\n# SIG # Begin signature block...",
  "digestAlgorithm": "SHA-256",
  "timestamped": true,
  "signerSubject": "CN=Example Code Signing",
  "certificateSerialNumber": "1234abcd"
}
```

The full contract is in
[`specs/PS-SIGN-001/contracts/openapi.yaml`](specs/PS-SIGN-001/contracts/openapi.yaml).
Errors use `application/problem+json`. Send `X-Correlation-ID` to correlate a
request with service logs; otherwise the service creates one.

## Configuration

The process fails fast if the signing identity is missing, unreadable, expired,
not a private-key entry, or not permitted for code signing.

| Environment variable | Required | Default | Purpose |
| --- | --- | --- | --- |
| `SIGNING_KEYSTORE_PATH` | Yes | none | Mounted PKCS#12 (`.p12`/`.pfx`) path |
| `SIGNING_KEYSTORE_PASSWORD` | Yes | none | PKCS#12 store password |
| `SIGNING_KEY_PASSWORD` | No | store password | Private-key password |
| `SIGNING_KEY_ALIAS` | No | sole key entry | Alias to use when more than one key exists |
| `SIGNING_TIMESTAMP_ENABLED` | No | `true` | Require RFC 3161 timestamping |
| `SIGNING_TIMESTAMP_AUTHORITIES` | No | Sectigo URL | Comma-separated HTTPS timestamp authorities |
| `SIGNING_TIMESTAMP_RETRIES` | No | `2` | Timestamp retry count |
| `SIGNING_TIMESTAMP_RETRY_WAIT_SECONDS` | No | `2` | Seconds between retries |
| `SIGNING_MAX_SCRIPT_BYTES` | No | `1048576` | Maximum UTF-8 request script size |
| `SIGNING_TEMP_DIRECTORY` | No | JVM temp directory | Ephemeral working directory |

Supply passwords through the deployment platform's secret mechanism. Mount the
PKCS#12 file read-only, limit access to the service identity, and do not bake it
into a container image. Timestamping requires outbound HTTPS access to every
configured authority.

Authentication, authorization, TLS termination, request throttling, and network
policy are expected at the trusted ingress/service-mesh layer. Do not expose the
service directly to an untrusted network.

## Run locally

Prerequisites: Java 17+ and a code-signing PKCS#12 file.

```bash
export SIGNING_KEYSTORE_PATH=/absolute/path/to/code-signing.p12
export SIGNING_KEYSTORE_PASSWORD='store-password'
export SIGNING_KEY_PASSWORD='key-password'
./mvnw spring-boot:run
```

Then invoke it:

```bash
curl --fail-with-body \
  -H 'Content-Type: application/json' \
  -H 'X-Correlation-ID: local-example' \
  -d '{"fileName":"hello.ps1","scriptContent":"Write-Output \"Hello\""}' \
  http://localhost:8080/api/v1/powershell/signatures
```

Health probes are available at `/actuator/health/liveness` and
`/actuator/health/readiness`.

## Build and test

```bash
./mvnw clean verify
```

The tests generate a short-lived code-signing identity outside the source tree,
sign a real PowerShell script, compare the unsigned Authenticode digest, verify
the embedded CMS signature cryptographically, check cleanup, and exercise the
HTTP contract and controlled failures.

## Container

```bash
docker build -t script-sign:local .
docker run --rm -p 8080:8080 \
  --read-only \
  --tmpfs /work:rw,noexec,nosuid,size=16m \
  --mount type=bind,src=/absolute/path/to/code-signing.p12,dst=/run/secrets/code-signing.p12,readonly \
  -e SIGNING_KEYSTORE_PATH=/run/secrets/code-signing.p12 \
  -e SIGNING_KEYSTORE_PASSWORD='store-password' \
  -e SIGNING_TEMP_DIRECTORY=/work \
  script-sign:local
```

The image runs as an unprivileged user. Prefer a secret-file or workload-identity
integration over literal command-line environment values in production.

## Windows verification

Save `signedScript` exactly as returned and verify it on Windows:

```powershell
$signature = Get-AuthenticodeSignature -FilePath .\hello.ps1
$signature | Format-List Status, StatusMessage, SignerCertificate, TimeStamperCertificate
if ($signature.Status -ne 'Valid') { throw "Signature verification failed: $($signature.Status)" }
```

The signing and timestamp certificate chains must be trusted on the verifying
machine. A test certificate generated by the automated suite is intentionally
not trusted outside that test.
